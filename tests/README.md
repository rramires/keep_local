# Tests

No npm packages are required. Node 24 (native WebSocket and Web Crypto) and Chromium are used.

```
node --test tests/unit
mkdir -p /tmp/keeplocal-base-571fcb7
git archive 571fcb7 | tar -x -C /tmp/keeplocal-base-571fcb7
KL_BASE_ROOT=/tmp/keeplocal-base-571fcb7 CHROME_BIN=/path/to/chromium node tests/browser/run.mjs
bash build-extension.sh
node tests/build/extension.mjs
```

The browser runner binds only to 127.0.0.1 and creates disposable browser contexts/profiles with fictitious data. Missing Chromium is reported as SKIP and does not satisfy browser acceptance. Set KL_BASE_ROOT to a directory produced by `git archive 571fcb7` for every browser run, including when v1 fixtures already exist. Fixtures are encrypted exports generated by the original application and contain only the published fictitious test password.

Legacy imports are limited to 64 MiB per file, 10,000 notes and 2 MiB per
serialized UTF-8 note. All records must authenticate and match their outer IDs
and timestamps before the atomic replacement. V1 cannot detect removal of an
entire record; authenticated v2 backups address this limitation.

Phase 2b adds unreadable-record recovery/discard, cancelled and failed exports,
concurrent record protection, password rotation and own-backup restoration;
17 card/modal action failure cases and second-write rollback for collective labels
and ordering; a legacy predictable-password login; and a pure password-policy table.
The archive assertion runs after build and keeps vendor support files out of the
ZIP while library SHA-256 verification still runs against tracked source files.
The independent reviewer probes and real unpacked-extension/UI compatibility
scripts are preserved under the owner's ignored `_temp/` folder.

The File System Access spike is a separate disposable package outside Git. It
adds no synchronization behavior to this app. Automatic folder writing and the
password/key section remain blocked pending explicit owner authorization.
